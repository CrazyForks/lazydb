# Oracle 表编辑器类型说明

## 默认列类型

在 Oracle 新建表或新增列时，LazyDB 默认使用：

```sql
VARCHAR2(255 CHAR)
```

`CHAR` 表示长度按字符数解释，而不是按字节数解释。255 只是表单提供的默认值，用户可以根据实际业务修改。

## 常用类型选择

| 数据 | 推荐类型 | 说明 |
| --- | --- | --- |
| 普通短文本 | `VARCHAR2(n CHAR)` | 适用于名称、编码、状态等字段 |
| 大段文本 | `CLOB` | 适用于超过普通字符串字段长度的文本 |
| 整数或精确数值 | `NUMBER` 或 `NUMBER(p,s)` | `p` 为精度，`s` 为小数位 |
| 日期 | `DATE` | Oracle 的日期类型，同时包含时间部分 |
| 高精度时间 | `TIMESTAMP` | 需要更细时间精度时使用 |
| 二进制内容 | `BLOB` | 适用于二进制对象 |

## `TEXT` 错误

Oracle 没有 PostgreSQL 等数据库中的通用 `TEXT` 内置类型。输入以下类型会在预览前被拒绝：

```sql
TEXT
```

请根据数据规模改为：

```sql
VARCHAR2(255 CHAR)
-- 或
CLOB
```

LazyDB 不会在执行阶段静默把 `TEXT` 转换为 `CLOB`，因为这会改变字段的存储、索引和比较语义。

## 自定义类型

带 schema 的自定义类型可以继续使用，例如：

```sql
APP.ADDRESS_TYPE
```

本地校验只阻断能够确定无效的声明。无法在不查询数据库元数据的情况下确认的类型会保留给 Oracle 最终验证。

## 当前表编辑能力

Oracle 新建表目前支持列名、原生类型、默认表达式、可空性以及表名等已实现字段。

已有 Oracle 表的编辑当前主要支持表名重命名。identity、生成表达式、collation、列注释以及复杂的 `ALTER TABLE` 变更不会被静默转换为其他 SQL；如未实现，计划生成阶段应明确返回不支持或校验错误。
